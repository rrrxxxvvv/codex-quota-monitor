# Codex Quota Monitor v1.7.1

Windows 桌面额度监控：读取本机已登录 Codex 的额度，额度重置或增加后显示持续置顶提醒；可按时间或额度刷新规则发送自定义消息，并可将额度上传到 AstrBot，通过 QQ 查询和接收通知。

这是个人项目，不是 OpenAI 官方产品。只显示接口实际返回的额度窗口，不假定所有套餐都有五小时和周额度。

## 两个仓库的关系

| 项目 | 运行位置 | 职责 |
| --- | --- | --- |
| 本仓库 | 登录 Codex 的 Windows 电脑 | 采集额度、本地提醒、自动规则、上传 |
| [astrbot_plugin_codex_quota](https://github.com/rrrxxxvvv/astrbot_plugin_codex_quota) | 运行 AstrBot 的服务器 | 接收并按 QQ 保存额度、私聊查询和推送、重置卡到期提醒 |

只使用本地监控时不需要插件。需要 QQ 功能时必须安装两端；插件不能自行登录你的电脑查询 Codex。两端使用同一连接密钥，上传格式为 v2，路径为 `/v1/quota`。

## 环境依赖

- Windows，Windows PowerShell 5.1、.NET/WPF、Windows Script Host。界面不支持 Linux/macOS。
- 便携包内置 Node.js，无需另行安装。直接运行源码时需要 Node.js 22 或更高版本，`node.exe` 位于 PATH；无需 `npm install`，仅使用 Node 内置模块。
- 本机安装并登录 Codex。脚本通过 `codex.exe app-server --stdio` 读取额度，需要对应版本提供 `account/rateLimits/read` 等接口。
- 默认查找 `%LOCALAPPDATA%\OpenAI\Codex\bin` 中的可执行文件，也会回退到 PATH 中的 `codex.exe`。可通过环境变量 `CODEX_QUOTA_CODEX_PATH` 指定完整路径。

## 启动

普通用户使用 `CodexQuotaMonitor-版本-win-x64-portable.zip`（Windows ARM64 使用对应 arm64 包），先完整解压，再进入 `CodexQuotaMonitor` 文件夹双击 `Start.vbs`。保留 `runtime` 文件夹，不要在 ZIP 内直接运行。仍需在本机安装并登录 Codex，Windows PowerShell 5.1、.NET/WPF 和 Windows Script Host 也需要可用。

GitHub 的自动生成 `Source code (zip)` 是源码包，不包含 Node.js。便携包通过下述脚本生成。

下载源码到可写目录，双击 `Start.vbs`。也可以从仓库目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Monitor.ps1
```

`Settings.vbs` 直接打开自动规则。关闭主窗口会收起到托盘；选择“退出监控”才停止。程序需保持运行，电脑睡眠或关机时不会采集。

默认每分钟采集一次；异常会退避重试。额度恢复或重置通知持续置顶，直到手动关闭。首次读取和账号切换只建立基线，不假报重置。

## 制作无需安装 Node.js 的便携包

打包电脑只需 Windows PowerShell 5.1 和网络，无需安装 Node.js 或 npm。在源码目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Build-Portable.ps1
# 可选：制作 Windows ARM64 包
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Build-Portable.ps1 -Architecture arm64
```

输出在 `dist/`，包含 ZIP 和 SHA-256 校验文件。脚本从 [Node.js 官方发布目录](https://nodejs.org/dist/v24.22.1/) 下载固定版本，校验官方 SHA-256，仅提取 `node.exe` 与许可证。下载缓存放在 `.build-cache/`，二次构建可复用。支持 `-OutputDirectory` 指定输出位置。

这是包含运行时的便携文件夹包，解压即用，无需安装 Node.js、npm 或修改 PATH；不是单文件 EXE。打包采用源文件白名单，不会带入 `data/`、密钥、QQ、账号状态或历史备份。不要直接压缩自己正在运行的整个目录进行分发。升级时退出监控，替换程序文件，保留自己的 `data/`。

## 自动执行规则

在“自动执行规则”中新增、保存并启用规则：

- 每日定时：用时分控件添加时间，也可填写北京时间，如 `08:00, 13:00, 18:00`。
- 指定日期时间：用日历和时分控件添加一个或多个时刻，每条规则最多 100 个。例如只在 `2026-11-01 08:00` 执行，或添加多个不规律的日期。
- 按间隔重复：选择首次执行日期时间，设置每隔多少分钟、小时或天执行。间隔范围为 1 分钟至 365 天，按开始时间计算，不随任务耗时推迟。
- 额度刷新：可选五小时、每周或任一窗口，检测到符合条件的变化后执行，同一周期去重。
- 程序运行完毕信号：界面预留选项，暂未开放，不能启用。
- 消息内容：每条规则独立设置，支持多行，1–20000 字；旧规则自动沿用“你好”。
- 发送方式：默认“追加消息”，在原任务末尾发送并保留全部历史，适合“继续”等工作消息。也可选择“编辑末条用户消息并重发”，并勾选允许替换最后一轮。两种方式均可配合任意时间或额度刷新触发器及自定义内容。
- 运行方式：始终开启、仅执行一次、触发 X 次后关闭；均显示已触发次数。按发起发送计数，忙碌跳过不计数，发送结果不确定时也保留计数以避免重复。重新启用并保存会重置本轮计数。
- 会话留空：首次创建专用任务，名称为规则名称，ID 自动回填并固定复用；也可填写已有 `codex://threads/…` 链接或 ID。

追加模式固定复用任务，保留已有对话并发送一条新消息，不调用历史回退接口。编辑末条模式只回退最后一轮，再发送规则里保存的内容，**替换最后一轮用户消息及对应回复，保留此前各轮历史**；执行前保存内容备份，并检查前序历史没有变化。如果最后一轮含多条用户消息（例如运行中补充过指令），接口无法只回退其中一条，监控会停止并提示手动处理，不会替你删除整轮。修改消息内容或发送方式不会更换会话，也不会重置触发计数。新建会话沿用只读权限和禁止审批设置；填写自定义内容不会自动授予文件写入、命令审批或额外工具权限。

**从 v1.5.5 及更早版本升级到 v1.6.0：没有发送方式字段的旧规则一律暂停，包含原先发送“你好”的规则。** 在规则页明确选择方式、保存并启用后才继续；不会依据消息内容自动猜测用途。旧版“编辑首条”行为已移除，旧 `replaceFirst` 配置同样暂停。已有异常暂停不会自动解除。升级前已回退的历史不会自动还原；`data/history-backups` 是执行前导出的 JSON 内容备份，不是可直接覆盖 Codex 数据库的完整备份。

所有日期时间按北京时间（UTC+8），精确到分钟。电脑和监控需保持运行，过期定时不补发；指定日期全部过去后没有下次执行。忙碌跳过的时刻不补发，也不占次数。长任务提交后保留本地运行连接并继续检查，后续触发先检查空闲状态；退出监控会关闭这些连接，尚未确认完成的任务会暂停对应规则，需检查会话后重新启用。账号不符、提交结果不确定或任务异常时不会贸然重发。

发送会消耗实际额度；是否开始或改变额度计时由服务端决定，本项目不保证问候一定改变重置时间。

### 与 Codex 桌面端同时运行

可以保持桌面端打开并使用其他任务。监控通过自己启动的 `codex.exe app-server --stdio` 进程调用接口，不需要连接桌面端的网络端口。写入占用针对具体任务，并非整个 Codex 接口只能由一个程序使用。

计时用途建议首次将会话 ID 留空，让监控创建并固定绑定专用任务。继续工作时可选择追加模式并填写已有任务 ID。目标任务未被其他客户端加载时，两种模式均可固定复用 ID，无需每次新建任务或关闭桌面端。若在桌面端打开目标任务，可能与监控争用写入连接。

**“从未加载目标任务”和“打开过以后切走”不同。** 后者仍可能保留写入占用，监控无法通过自己的连接替另一个客户端释放它。v1.7.0 可选择下述回退通道；仅接口模式仍跳过本次，不计次数、不补发。界面是否预加载任务取决于 Codex 版本，不能仅凭当前显示的是其他任务就断言目标已释放。

### 占用时的三通道回退（v1.7.0）

规则页可选“界面发送（默认）”“仅接口”“接口 → 界面操作”“接口 → 界面操作 → 退出客户端后接口发送并重开”。v1.7.1 起新规则默认直接界面发送，不先尝试接口；已有规则保留原选择。最后一种须勾选允许关闭客户端。

“界面发送”通过只读接口核对账号、任务历史和完成状态，发送操作直接走界面；明确未发送时跳过，不自动改用接口或关闭客户端。任务 ID 留空时，首次创建仍由接口发送首条消息以初始化历史并固定绑定 ID，后续触发直接使用界面。要从第一条消息开始就走界面，请填写已有任务 ID。

1. 优先调用独立 app-server 接口。只有明确的写入占用错误才进入下一通道。
2. 界面通道通过 Windows UI Automation 定位控件，再操作键鼠。打开目标任务，通过任务菜单复制深度链接核对 ID，检查草稿、空闲状态和消息内容后点击发送。支持追加、编辑末条以及多行内容；编辑前保存历史，提交后核对前序历史。
3. 界面明确未提交且已恢复时，授权规则可以关闭整个本机 Codex 客户端及其后台，通过独立接口发送，**等消息任务结束并关闭监控写入连接后再重开客户端**。重开在发送之后，避免重新抢占。此步骤可能中断桌面端其他任务，无法只强制释放一个任务。请从桌面快捷方式独立启动监控；若监控属于 Codex 自身进程树，会拒绝结束祖先进程。

界面通道需要解锁桌面，会暂时占用前台和键鼠。已有草稿不覆盖；用户输入、前台切换或锁屏会停止后续回退。可能已提交、草稿清理未确认或历史不匹配时暂停规则，不切换通道重发。目标任务仍在正常运行时不会强行中断。

坐标取自控件实时位置，不写死屏幕位置，也不依赖皮肤颜色。当前任务菜单支持中英文标签，未识别的语言、多个主窗口或不唯一的编辑按钮会明确失败，不盲点。本机中文界面已做实际操作验证；其他分辨率、缩放、皮肤和客户端版本仍需对应环境验证。

每次界面操作在 `data/ui-automation/<运行ID>/` 保存 `status.json` 和 `helper.log`，临时消息计划结束即删除。关闭和重开助手在 `data/desktop-release/<运行ID>/status.json` 保存状态，监控意外退出时会尝试重开。规则状态区显示实际通道及完整日志路径。历史备份与规则配置包含用户内容，请勿随包分发。

## QQ 对接

1. 先按配套插件 README 安装服务器端。插件首次加载自动生成密钥，重新打开配置页复制。
2. 桌面主窗口打开“AstrBot 推送”，勾选启用远程上传。
3. 填写服务器 `IP:端口`（默认端口 `18765`），或 HTTPS 根地址。
4. **必须填写绑定 QQ 号**，并填入插件生成的相同密钥。
5. 设置上传间隔，范围 15–86400 秒，默认 60 秒，保存后自动生效。

额度仍每分钟采集，上传只发送新结果。长间隔会延迟提醒，超过 3 分钟未采集的数据会被插件标记过期。上传失败按所设间隔重试。

机器人只向绑定 QQ 推送；该 QQ 私聊 `/额度查询` 只会收到自己的额度。推送开关和到期提醒见配套插件 README。

上传含 QQ、账号及卡标识的哈希、额度比例和时间，不含登录凭证或聊天记录。HTTP 使用 HMAC 签名但不加密内容，公网需要保密时使用 HTTPS。服务器密钥只应交给可信的上传端。

## 重置卡

显示只读接口返回的剩余可用次数与到期时间，不会使用或核销重置卡。配套插件在每张卡不足 7 天、不足 24 小时时分别提醒一次。到期提醒需要最近 3 分钟内的有效上传；离线会延迟。

## 数据与排错

运行配置、密钥、QQ、监控状态、历史备份和日志均在自动生成的 `data/` 中，整个目录已被 Git 忽略。**发布源码或报错截图时不要附上该目录。**

v1.5.4 起，报错区域会显示对应日志或状态文件的完整路径，可选中复制，也可点击“打开日志文件夹”。路径根据实际运行目录生成；正常状态下收起。启动失败弹窗也会显示错误日志路径。

| 情况 | 对应文件（位于程序的 data 目录） |
| --- | --- |
| 规则执行报错、会话占用 | `schedule-state.json`（执行记录与错误详情）、`schedule-status.json`（当前状态） |
| 额度读取失败 | `status.json`（当前错误状态） |
| AstrBot 上传失败 | `remote-status.json`（当前错误状态） |
| 界面或保存操作异常 | `ui-errors.log`（发生异常时生成） |
| 主程序启动失败 | `startup-error.txt` |

提交问题时只提供相关错误条目即可；不要发送 `remote-config.json`，其中包含连接密钥。

v1.6.0 的发送后校验异常会在 `schedule-state.json` 对应执行记录内写入 `historyCheck`，记录返回的轮次 ID、状态、用户消息数量及匹配结果，不额外保存消息正文。追加模式只验证本次新消息，不再要求整个任务只有一轮。

- 找不到 Node：安装 Node 并重新启动程序，确认 `node --version` 可用。
- 连接被拒绝：确认插件已启用、服务已监听、Docker 映射接收端口。
- 连接超时：检查地址、服务器安全组及防火墙。
- HTTP 401：确认两端密钥一致、系统时间正常。
- HTTP 400：确认两端均为支持 QQ 绑定的版本，QQ 已填写。
- 未返回某个额度或卡信息：显示未知，不用余额或其他数据推算。
- `already has an active writer`：另一个 Codex 客户端仍持有该会话的写入连接，即使任务已经完成也可能占用。v1.7.0 按规则选择仅接口跳过、界面发送或授权关闭客户端后发送。提交结果不确定会暂停，避免重复。仅重新勾选规则不能解除占用。旧版本因此已停用的规则，升级后需手动重新启用一次。

关闭任务页不一定立即释放连接：[官方 app-server 文档](https://learn.chatgpt.com/docs/app-server#unsubscribe-from-a-loaded-thread)说明，最后一个订阅者退出后，服务还有 30 分钟无订阅、无活动的卸载宽限期。若需要立即释放，先确认对应客户端没有其他运行中的任务，再退出该客户端。监控本身通过独立本地服务运行，使用已有本机 Codex 登录，不要求桌面窗口一直打开。

接口或 Codex 版本变化可能影响兼容性。测试覆盖本地额度判断、规则执行、上传重试，以及配套插件的模拟联调；无法保证所有客户端版本均兼容。

另可运行 `node tests/test-writer-integration.cjs`。它需要已安装 Codex 可执行文件，但不需要登录账号：测试创建隔离的 Codex 配置与会话目录，连接本机 HTTP 模拟模型，使用真实 app-server 验证双客户端写入冲突、释放占用后编辑末条重发、固定会话和计数上限。还验证两个客户端共享同一测试目录时，一个持续运行其他任务，监控仍可首次创建绑定并连续重发；只读列表/历史不会加载目标任务，而恢复后立即退订仍可能保留写入占用。测试不读取个人会话或调用真实模型，也不操作桌面界面，不能据此保证所有桌面版本的任务预加载行为或其他电脑的运行状态。

三通道测试包括模拟客户端的故障保护，以及真实 app-server 的占用、释放、发送和重新获取写入连接；桌面进程生命周期由 `test-desktop-release.ps1` 模拟进程表验证。这些测试不会退出真实桌面客户端。真实桌面整体退出/重开未在开发中的 Codex 会话内执行。

桌面 v1.7.0 的增强不改变上传格式，QQ 通知设置继续兼容插件 v1.4.0，无需同步升级插件。

## 桌面端通知设置（v1.4.0）

在桌面“AstrBot 推送”中分别控制每周额度更新、周期外重置及可用额度增加、重置卡到期提醒。设置随额度上传，按 QQ 保存。默认全部开启，Bot 私聊关闭推送仍为总开关，查询不受影响。五小时等其他正常周期更新保留原行为。

到期阈值输入逗号分隔的天数，例如 `14, 7, 1`；允许 1–365 天整数、最多 10 项，默认 `7, 1`。每张卡每档只提醒一次，新加阈值若已满足会触发判断；已提醒过的阈值关闭再开启不会重复。关闭类别会取消尚未发送的对应提醒。

修改设置会立即尝试同步，无需等待新采集；需两端均更新至 v1.4.0。上传未启用或网络不可用时，服务器继续沿用最后成功收到的设置。
